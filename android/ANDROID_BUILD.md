# Building the AI Switchboard Android app from source

This guide explains how anyone can compile the **AI Switchboard** Android app from this repository and produce an APK they can install on their own phone. You do **not** need the official APK to use the app: you can build your own.

The app is a companion for the AI Bluetooth Phone Assistant switchboard. It opens the switchboard's Web GUI through an embedded Tor client and can show notifications. See the main [README](../README.md#-android-app-ai-switchboard) for what it does.

> **Important:** an APK you build is signed with **your** key, not the author's. Android treats it as a different publisher, so it cannot be installed *over* the official APK (and vice versa). Uninstall one before installing the other. You will also need to pair the app again.

---

## 1. Repository layout

The Android project lives in the `android/` folder of this repository. That folder is a complete Gradle project:

```
android/
├── settings.gradle.kts
├── build.gradle.kts            # project-level build file
├── gradle.properties
├── gradle/                     # Gradle wrapper (and version catalog, if present)
├── gradlew, gradlew.bat        # Gradle wrapper scripts
├── ANDROID_BUILD.md            # this guide
└── app/
    ├── build.gradle.kts        # app module (dependencies, SDK versions, app version)
    └── src/main/
        ├── AndroidManifest.xml
        ├── java/com/aiphone/switchboard/   # Kotlin sources
        ├── res/                            # layouts, theme, icons and texts (values/ = English, values-es/ = Spanish)
        └── assets/licenses/                # license texts shown in About → Licenses
```

Nothing generated by the compiler (`build/`, `.gradle/`, `.idea/`, `local.properties`) and no signing keys are stored in the repository.

## 2. What you need

| Requirement | Notes |
|---|---|
| **Android Studio** (current stable) | Includes the JDK (17) and everything needed to build. <https://developer.android.com/studio> |
| **Android SDK Platform 36** | Install it in Android Studio: *Tools → SDK Manager → SDK Platforms*. The project uses `compileSdk = 36` / `targetSdk = 36`; the minimum supported Android is 7.0 (API 24). |
| **Internet access** (first build) | Gradle downloads the dependencies (AndroidX, Kotlin, WorkManager, `tor-android`, ...). |
| **Git** (optional) | To download the source: `git clone`. You can also use *Code → Download ZIP* on GitHub. |

You do not need a Google account, a Google Play developer account or any API key to build the app.

## 3. Get the source

```bash
git clone https://github.com/antor44/AI-Bluetooth-Phone-Assistant.git
cd AI-Bluetooth-Phone-Assistant/android
```

## 4. Open and test it (debug build)

1. Start **Android Studio** → **Open** and select the **`android`** folder (the one that contains `settings.gradle.kts`, not the repository root).
2. Wait for **Gradle sync** to finish. Android Studio creates `local.properties` with the path of your SDK automatically (this file is private to your computer and is not part of the repository).
3. If Android Studio reports that the **Android Gradle Plugin** does not support `compileSdk 36`, accept the suggested upgrade (*AGP Upgrade Assistant*), or update the plugin version in the project files.
4. Connect a phone with **USB debugging** enabled (or start an emulator) and press **Run ▶**.

You can also build from the command line (from the `android` folder):

```bash
./gradlew assembleDebug          # Windows: gradlew.bat assembleDebug
# result: app/build/outputs/apk/debug/app-debug.apk
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

A debug build is signed with an automatic debug key. It is fine for your own testing, but build a **release** APK (next sections) for daily use.

---

## 5. Create your own signing key (once)

Android only installs signed APKs. Create a key with the JDK's `keytool` (or use Android Studio's wizard, see below):

```bash
keytool -genkeypair -v -keystore my-release-key.jks -alias aiswitchboard \
        -keyalg RSA -keysize 4096 -validity 10000
```

It asks for a password and some identity data. Then:

* **Store the `.jks` file outside the project folder** and **never commit or share it**.
* **Back up the file and the passwords.** Every future update must be signed with the same key; if you lose it, you (and your users) must uninstall and reinstall.

---

## 6. Build the signed release APK

### Option A — Android Studio wizard
1. **Build → Generate Signed App Bundle / APK…** → choose **APK** → *Next*.
2. Select your keystore file, alias and passwords (or create a new keystore here instead of using `keytool`) → *Next*.
3. Choose the **release** build variant, tick both signature versions (**V1 and V2**) → *Create*.
4. The APK is created in `app/release/` (Android Studio shows a *locate* link).

### Option B — Command line
```bash
./gradlew assembleRelease
# unsigned result: app/build/outputs/apk/release/app-release-unsigned.apk

# apksigner and zipalign are in <Android SDK>/build-tools/<version>/
zipalign -v -p 4 app/build/outputs/apk/release/app-release-unsigned.apk app-release-aligned.apk
apksigner sign --ks /path/to/my-release-key.jks --out AI-Switchboard.apk app-release-aligned.apk
apksigner verify --print-certs AI-Switchboard.apk
```

---

## 7. Install it on your phone

1. Copy `AI-Switchboard.apk` to the phone (USB cable, cloud storage, ...) or install it with `adb install -r AI-Switchboard.apk`.
2. Open the file on the phone. Android asks you to allow **Install unknown apps** for the app you used to open it (file manager / browser). Allow it only for that app, then tap **Install**.
3. Google Play Protect may warn that the app comes from an unknown developer. That is expected for apps not distributed through Google Play: tap *More details → Install anyway*.
4. Open the app, accept the **notifications** permission (Android 13+), and pair it with your switchboard (see the main README).

## 8. Settings you may want to know

| Setting | Where | Notes |
|---|---|---|
| App version | `app/build.gradle.kts` → `versionName`, `versionCode` | Raise `versionCode` by 1 for every new build you want to install over a previous one. |
| Application id | `app/build.gradle.kts` → `applicationId` (`com.aiphone.switchboard`) | If you publish your own modified version, use your own id so it does not clash with the original. |
| Notifications port | `AppConfig.kt` → `NOTIFY_PORT` (default `8502`) | Must match the **`tor_notify_port`** setting of the switchboard (default `8502`). |
| Keep Tor connected after each check | `AppConfig.kt` → `RELEASE_TOR_AFTER_POLL` | `true` (default) saves battery; `false` is faster but uses more. |
| Check intervals and timings | `AppConfig.kt` | Balanced-mode choices (`BALANCED_INTERVAL_CHOICES_MINUTES`), the long-request length of Instant mode, retry delays and the default day/night hours. |
| Colours and theme | `res/values/colors.xml`, `res/values-night/colors.xml`, `res/values/themes.xml` | One Material 3 theme for all screens, with light and dark colours. |
| Smaller APK | `app/build.gradle.kts` | Tor ships native libraries for several processors. To keep only ARM devices add inside `defaultConfig`: `ndk { abiFilters += listOf("arm64-v8a", "armeabi-v7a") }` (removes support for x86 emulators). |

## 9. Troubleshooting

| Problem | Solution |
|---|---|
| *Unsupported compileSdk 36* / Gradle sync error about the plugin | Update the Android Gradle Plugin (Android Studio's *AGP Upgrade Assistant*), and install *Android SDK Platform 36*. |
| *SDK location not found* | Open the folder in Android Studio once (it creates `local.properties`), or create it yourself with `sdk.dir=/path/to/Android/Sdk`. |
| *Could not resolve* dependency errors | Check your Internet connection or proxy and sync again. |
| *Unresolved reference: R.drawable.ic_stat_notify* (or other `R.` resources) | The `res/` folder is incomplete: restore it from the repository. |
| *The keystore was tampered with, or password incorrect* | Wrong keystore or key password. |
| *INSTALL_FAILED_UPDATE_INCOMPATIBLE* / "App not installed" over an existing install | The installed app was signed with a different key. Uninstall it first. |
| The app installs but the old icon stays | Uninstall the previous version; the launcher caches icons. |
| *Connecting through Tor…* never finishes | The first connection can take 1–3 minutes; if it seems stuck, press **Refresh** (↻) or **Retry**, which restart Tor from scratch. Check that the switchboard's *Remote access (Tor)* panel is **Active** and that your network does not block Tor. |

## 9b. Adding another language

All texts of the app are in `app/src/main/res/values*/strings.xml`. Android picks the file that matches the phone's language and falls back to English (`values/`).

1. Copy `res/values-es/strings.xml` to a new folder named after the language, for example `res/values-fr/strings.xml` (French), `res/values-de/strings.xml` (German) or `res/values-pt/strings.xml` (Portuguese).
2. Translate the text between the tags. Do **not** change the `name="..."` values, and keep placeholders such as `%1$d` or `%1$s` exactly as they are.
3. Strings marked `translatable="false"` (legal texts and licence names) stay in English and must not be copied.
4. Build again. No Kotlin code needs to change.

If a text is missing in your new file, the English one is shown for that line only.
